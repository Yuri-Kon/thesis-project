## 1. 文档目的与时间范围

- 目的：在不改动系统契约（FSM/HITL/Agent 边界）的前提下，形成可落地、可复现、可审计的实验方案，用于：
  - 支撑中期报告中的“算法有效性 + 工程可用性”论证；
  - 作为 2026-03-16 至 2026-03-23（W12）执行与验收依据；
  - 对齐 W11/W12 已立项 issue 的实现与评估口径。

## 2. 研究问题与假设

- RQ1（纵向有效性）：从退化基线到完整方法，关键机制是否带来稳定增益？
- RQ2（横向实用性）：与社区主流代理范式相比，系统表现是否“效果不差、治理更强”？
- RQ3（代价可控性）：性能提升是否在时延/成本可接受范围内？

对应假设：

- H1：A0→An 的最终任务成功率显著提升。
- H2：每个机制增量对其目标指标有正向影响（例如硬校验提升 schema 合法率）。
- H3：完整方法在效果上优于或接近 E0/E1/E2，且治理指标显著更好。
- H4：完整方法相较 A0 的成本增幅可控（以时延与 token/调用成本衡量）。

## 6. 横向对比（E0-E2）

在相同数据集、相同工具白名单、相同预算上进行公平比较。

| 组别 | 基线范式 | 实现约束（公平性） | 主要对比点 |
| --- | --- | --- | --- |
| E0 | ReAct-style 单轨迹代理 | 单候选/单轨迹，统一工具与超参数预算 | 简洁路径下的成功率与成本 |
| E1 | ToT-style 多分支推理 | 多分支候选 + 分支投票/选择，预算与 A1/A2 对齐 | 分支搜索收益与时延代价 |

说明：横向实验必须把“治理能力”作为同等一级指标，而不仅是成功率。

## 7. 指标体系与计算口径

### 7.1 效果指标

- 最终任务成功率：`#DONE / #全部任务`。
- 首轮成功率：不触发 patch/replan 且一次主链路完成的比例。
- 约束满足率：满足长度/字符/结构/QC 等硬约束的任务比例。

### 7.2 机制指标

- Schema 合法率：候选中通过 schema 校验的比例。
- 候选可执行率：候选中通过可执行性校验（I/O 闭包、工具可用、参数合法）的比例。
- 平均 patch 次数、平均 replan 次数。
- suffix_replan 前缀保持率。
- WAITING 命中正确率：触发 WAITING 的事件中，满足门控规则（风险/成本/失败阈值）的比例。

### 7.3 代价指标

- 端到端时延：任务从 CREATED 到 DONE/终态的耗时（均值/中位数/P95）。
- 步骤耗时：`duration_ms` 聚合统计。
- token/算力成本：优先记录真实 token usage；若暂缺，使用“模型调用次数 + 远程调用次数 + GPU 时长”代理。

### 7.4 治理指标

- 审计链完整性：每次 WAITING 决策是否具备 `PENDING_ACTION_CREATED -> DECISION_SUBMITTED -> DECISION_APPLIED -> WAITING_EXIT` 与关键快照。
- 失败可追溯率：失败任务中可定位到 `step_id + tool_id + failure_code + 前后状态` 的比例。
- 决策回放成功率：按 EventLog 可无歧义重建状态迁移与决策结果的比例。

## 8. 统计检验与显著性

- 二元指标（成功率、合法率）：报告 Wilson 95% CI；组间采用配对 McNemar（同任务输入下）。
- 次数/时延指标：采用配对 bootstrap（10,000 次重采样）给出置信区间。
- 显著性阈值：`p < 0.05`；同时报告效应量（绝对提升百分点与相对提升）。

  - 应对：固定工具白名单、统一预算、公开 prompt/配置版本。
