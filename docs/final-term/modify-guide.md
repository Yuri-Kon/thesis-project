## 3. Word 字段与引用保护规则

当前 DOCX 中包含 Zotero 生成的引用域和 Word 原生交叉引用域。后续实际编辑时必须遵守以下规则：

- 不要对含 Zotero 引用的段落使用整段文本替换。
- 不要把 Zotero citation、bibliography 或 REF/SEQ 字段固化为普通文本。
- 修改含引用句子时，只改引用前后的普通文字，保留 `ADDIN ZOTERO_*`、`fldChar`、`instrText`、`hyperlink`、`bookmarkStart`、`bookmarkEnd` 等结构。
- 不要手动改写文末参考文献列表来替代 Zotero 刷新。
- 图题、表题和正文中的“图/表/代码清单/算法 + 编号”应优先保留或重建 Word 原生 `SEQ`/`REF` 交叉引用。
- 更新目录和图表编号时，使用 Word 的“更新域”功能，而不是手动改目录文本。
- 编辑后检查全文是否出现“错误!未找到引用源”或 “Error: Reference source not found”。
- 在目录、正文、表格内部文字中，不要开启“如果定义了文档网格，则对齐到网格”。
- 标题中不要带有标点符号。

### 5.3 可直接采用的改写句式

任务创建互斥校验：

```text
系统在任务创建模型中设置互斥校验逻辑，用于保证自然语言目标、兼容查询入口和已确认结构化任务规格三种输入方式不会同时出现。该约束不直接提高底层蛋白质设计模型的能力，但可以避免任务入口语义不清导致后续计划生成、状态迁移和审计记录难以解释。
```

StepRunner 重试逻辑：

```text
StepRunner 将单步执行过程封装为“输入解析、工具调用、输出校验、事件记录和失败处理”的统一链路。对于可重试错误，系统执行有界重试；当重试耗尽或错误类型不可重试时，StepRunner 返回结构化失败信息，由上层运行时根据失败上下文选择局部修补、后缀重规划或终止。
```

PendingAction 写入：

```text
HITL 在实现中被表示为可持久化的运行时状态，而不是前端页面上的临时按钮。系统进入 WAITING_PLAN_CONFIRM、WAITING_PATCH_CONFIRM 或 WAITING_REPLAN_CONFIRM 前，需要先写入 PendingAction、记录事件日志并保存 TaskSnapshot，使人工决策可以在页面刷新、服务重启或延迟处理后继续恢复。
```

RuntimeEvaluator 候选重排：

```text
RuntimeEvaluator 负责将运行时观测映射到候选排序调整。当策略模式禁用运行时重排，或 RuntimeState 尚不可用时，系统保留静态候选顺序；当 Lite belief-state / 轻量信念状态可用时，系统根据证据充分性、风险等级、预算压力和恢复需求计算运行时调整量，并据此更新候选的最终排序。
```

ToolAdapter 抽象接口：

```text
ToolAdapter 为外部蛋白质设计与分析工具提供统一调用边界。执行层不直接依赖 ProtGPT2、ProteinMPNN、ESMFold/OpenFold、Biopython QC 或目标评分工具的具体接口，而是通过适配器读取能力描述、解析输入、执行工具、规范化输出和错误信息。这样可以降低工具异构性对 PlanRunner 和 StepRunner 的影响。
```

## 6. 图的控制与版芯重绘指南

### 6.1 全局图示规范

所有正式插图应满足：

- 中文使用宋体。
- 英文、数字、代码缩写和变量名使用 Times New Roman。
- 图内字号优先五号字；内容较多时统一小五号。一个图内不得混用五号、小五号和 10 pt 等多种字号。
- 算法变量使用数学变量格式，变量斜体，下标按数学下标处理。例如 `g`、`C`、`K`、`h_t`、`o_t`、`x_t`、`S_static`、`U`。
- 图中节点、箭头、泳道和注释不得超出页面版芯。
- 不要通过截图或低分辨率压缩解决过宽问题。
- 横向过宽图应优先改成纵向层级结构、分栏结构、泳道结构，必要时拆成两个子图。
- 图中文字应能在最终 PDF 中清晰阅读，不得因缩放过度导致发虚。

### 6.2 图 2-1 技术路线概述

当前问题：

- 技术路线图信息量较大，容易横向展开。
- 图内如果同时放入蛋白质工具、科学工作流、LLM Agent、POMDP、CEBRA-WP 和实验验证，容易造成文字密集。

建议重绘方向：

- 第一层：“技术基础”，包含蛋白质设计工具、科学工作流、LLM Agent、部分可观测规划。
- 第二层：“系统方法”，包含 ProteinToolKG、FSM、HITL、CEBRA-WP。
- 第三层：“工程实现”，包含 API、Planner、Executor、ToolAdapter、EventLog、Snapshot。
- 第四层：“验证结果”，包含系统测试、84-run 消融、机制可观测性和边界说明。

推荐结构：

```text

  ↓

  ↓

  ↓
```


### 6.4 图 4-6 CEBRA-WP 算法闭环

当前问题：

- 算法闭环容易把静态候选生成、运行时观测、belief-state 更新、重排序和恢复动作全部挤在同一横向图中。

- 如果保留过多参与方，图会被迫缩小。

建议重绘方向：

- 将 Safety 和 Summarizer 作为运行时节点中的子步骤或旁路标注，不单独占很宽泳道。

- 修改后更新目录，确认目录中的章号正常。

### 7.2 标题样式统一

应统一设置：

- 一级标题：中文黑体或样板要求字体，居中，段前段后统一，编号与标题正文距离统一。
- 二级标题：左对齐，编号格式统一，段前段后统一。
- 三级标题：字号、加粗、缩进和段前段后统一。
- 标题不得依靠空段落制造间距。
- 标题后不得出现大面积空白或孤行。

验收标准：

- 全文一级标题风格一致。
- 二级、三级标题编号连续。
- 目录能自动更新。
- 无手写编号与自动编号混用。

### 7.3 目录样式统一

目录样式应作为独立样式统一设置，不要通过逐行手工调整解决。

必须检查：

- 目录整体行距设置为多倍行距 1.25 倍。
- 各级目录项均关闭“如果定义了文档网格，则对齐到网格”。
- 目录项字体、字号、缩进、制表位和页码对齐方式保持一致。
- 目录由 Word 域自动生成和更新，不手动改目录文本。

## 8. 正文段落与基础排版指南

正文样式建议统一处理，不要逐段手工修。

必须检查：

- 正文两端对齐。
- 正文样式取消“如果定义了文档网格，则对齐到网格”。
- 正文、目录、表格内部的文字均取消“如果定义了文档网格，则对齐到网格”。
- 正文、表格、图题、表题和目录中的中英文混排处，英文单词与中文文字之间不保留手动空格，例如写作“大语言模型Agent”“ProteinToolKG描述工具能力”，不要写成“大语言模型 Agent”“ProteinToolKG 描述工具能力”。
- 中文与数字之间的自动间距保持一致，避免局部段落因网格或自动调整出现异常拉伸。
- 段落之间不使用空段落制造距离。
- 段前、段后和行距通过样式控制。
- 含英文长串、公式、上标、软回车的段落不要出现异常拉伸。
- 页面中不出现超过约五分之一版面的异常空白。

建议正文段落格式：

- 中文正文使用宋体。
- 西文、数字使用 Times New Roman。
- 首行缩进 2 字符。
- 段前段后按学校样板统一，不手动插空行。
- 行距与样板保持一致，避免局部行距过松。

## 9. 图题、表题与表格规范

### 9.1 图题

- 图题放在图下方。
- 图题居中。
- 图题只使用中文表述。
- 中文使用宋体五号。
- 数字和英文使用 Times New Roman 五号。
- 图与图题之间不插入空段落。
- 图题与后续正文之间不依赖空段落制造距离。

### 9.2 表题

- 表题放在表格上方。
- 表题居中。
- 表题编号按章编号。
- 中文使用宋体五号。
- 数字和英文使用 Times New Roman 五号。
- 表题与表格应保持紧密视觉关系。

### 9.3 表格

- 表内文字统一使用宋体和 Times New Roman。
- 字号优先五号；内容较多时整表统一小五号。
- 同一张表内字号必须一致。
- 表内行距使用单倍行距。
- 不使用空段落调整表格与正文距离。
- 优先通过列宽、换行、压缩文字和统一小五号避免跨页。
- 如果表格内容过多，应拆分为两个逻辑表，而不是让一个大表跨越多页。

续表规则：

- 续表不创建新编号。
- 续表上方单独一行右对齐。
- 使用原表交叉引用并追加“（续表）”。
- 续表标识使用宋体五号字。

## 10. 参考文献与引用调整指南

### 10.1 数量与结构目标

目标：

- 参考文献总数控制在 25 条以内。
- 至少包含 5 条中文文献。
- 新增中文文献必须在正文中有自然引用位置。
- 不要只在文末塞入中文文献。

### 10.2 优先保留文献类型

优先保留：

- 蛋白质结构预测和蛋白质设计工具：AlphaFold、AlphaFold 3、ESMFold/OpenFold、ProteinMPNN、ProtGPT2、RFdiffusion、Rosetta、Biopython。
- LLM Agent 与工具调用：ReAct、Toolformer、Tree of Thoughts、Reflexion。
- 科学工作流与可复现执行：Nextflow、Pegasus。
- 决策理论与部分可观测规划：MDP、POMDP、预算感知决策。
- 系统测试、软件工程、科学工作流验证相关文献。

优先删减：

- 与正文贡献关系弱的泛背景文献。
- 同一观点下重复支撑的多篇外文文献。
- 正文只出现一次且不是关键依据的前沿预印本。
- 不能在正文自然引用的补充文献。

### 10.3 中文文献补充方向

可考虑补充中文文献的位置：

| 正文位置 | 中文文献方向 | 写法建议 |
|---|---|---|
| 第一章课题背景 | 蛋白质计算设计或人工智能辅助药物/蛋白质设计综述 | 用于说明国内相关领域对计算设计和 AI 辅助设计的关注。 |
| 第二章科学工作流 | 科学工作流、可复现计算或科研软件工程中文综述 | 用于支撑流程编排和可复现执行背景。 |
| 第二章 Agent 协作 | 大模型智能体、工具调用或多智能体协作中文综述 | 用于补充中文研究背景。 |
| 第三章需求分析 | 软件工程需求分析、系统可追溯性或人机协同系统文献 | 用于支撑需求与边界设计。 |
| 第六章验证 | 软件测试、系统测试、实验验证或可追溯测试证据文献 | 用于支撑测试覆盖和验证方法。 |

正文插入中文文献时应自然贴合原句，例如：

```text
在科研软件系统中，流程可追溯性和实验可复现性通常需要通过日志、配置、数据版本和执行环境共同保障[中文文献编号]。
```

### 10.4 Zotero 操作要求

- 使用 Zotero 更新文献条目和正文引用。
- 不手工改 Word 文末参考文献列表。
- 删除文献前先确认正文中对应引用已删除或替换。
- 更新后检查文末参考文献数量、中文文献数量和引用顺序。
- 检查 Zotero 字段是否仍可刷新。

## 11. 摘要、结论与边界表述同步

合并章节、删代码、删文献和改图后，需要同步检查摘要和结论。

摘要中应保留：

- 系统原型定位。
- ProteinToolKG、FSM、HITL、CEBRA-WP。
- 系统测试覆盖 13 个用例、12 个通过、1 个 CLI 相关用例部分通过。
- 84 runs 内部消融实验得到 81 个 DONE 和 3 个 FAILED。
- 结论限定在工作流层和工程原型层。

摘要中避免：

- 暗示候选蛋白已经完成湿实验验证。
- 将 CEBRA-WP 写成底层蛋白质生成模型。
- 将内部原型测试写成通用 benchmark 结论。

结论中应同步：

- 将“第六章和第七章”改为合并后的第六章。
- 保留实验规模有限、重规划触发不足、安全 block 批量压力不足等局限。
- 保留后续工作方向，但不要写成已完成事实。
