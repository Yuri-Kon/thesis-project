## 2.1 蛋白质计算设计的基础概念

### 2.1.1 蛋白质的序列—结构—功能关系

蛋白质是由 20 种标准氨基酸通过肽键连接而成的线性聚合物。在生理条件下，多肽链自发折叠为特定的三维构象（天然态），这一过程被称为蛋白质折叠。蛋白质的功能由其三维结构决定，而三维结构又由氨基酸序列编码——这一"序列决定结构、结构决定功能"的层级关系是蛋白质计算设计的理论基础。

de novo 蛋白质设计的核心问题可以形式化表述为：给定目标功能或结构约束，找到一条或多条氨基酸序列，使得这些序列能够折叠成满足约束的三维结构。该问题具有极高的搜索空间复杂度——对于长度为 n 的序列，理论候选空间为 20^n，即使将搜索限制在"类天然"序列子空间内，仍是一个高维组合优化问题。

### 2.1.2 de novo 蛋白质设计的一般流程

典型的 de novo 蛋白质设计流程包含六个主要阶段，这六个阶段在本系统中被组织为可组合的能力分层（详见第 4 章）：

**序列探索（Sequence Exploration）**：生成大量候选序列以覆盖目标空间。早期方法依赖基于物理力场的蒙特卡洛搜索（如 Rosetta），近年来的深度学习方法（如 ProtGPT2、ProteinMPNN）能够以语言模型或图神经网络的方式高效生成类天然序列。

**结构映射（Structure Projection）**：将候选序列映射为三维结构并评估折叠可靠性。AlphaFold2 通过多序列比对和 Evoformer 架构实现了原子级精度预测，ESMFold 则利用蛋白质语言模型的内部表征进行快速单序列预测，在速度和精度之间取得平衡。预测结果通常包含每个残基的 pLDDT 置信度分数。

**质量门禁（Quality Gate）**：对序列和结构进行硬性可行性过滤，剔除不符合物理规律、包含非法残基、长度越界或结构完整性不足的候选。该阶段的作用是在高代价的后续步骤（如结构精修、目标评分）之前尽早淘汰不可用候选，降低计算浪费。

**结构条件精修（Structure-conditioned Refinement）**：基于结构信息对序列进行重新设计或优化。ProteinMPNN 的核心能力正是从骨架结构反推最优序列，可以在固定骨架上生成多条候选序列，或用迭代设计-预测循环逼近目标结构。

**目标评分（Objective Scoring）**：对候选序列进行多目标评价和排序。评分维度根据设计任务的不同可以包括结构质量（pLDDT、RMSD）、稳定性（自由能、熔球温度）、溶解度、novelty（与已知序列的差异度）、功能性位点保留等。

**结果汇总（Summarization）**：将各阶段的产物——候选序列、结构文件、质量指标、安全评估和恢复轨迹——组织为可供科研人员阅读和复核的结构化报告。

## 2.2 大语言模型与 Agent 协作框架

### 2.2.1 大语言模型的能力与局限

大语言模型（Large Language Model, LLM）在 2023-2024 年间在多项科学任务中展示了显著的能力——包括蛋白质序列理解、工具选择建议、失败分析和文本报告生成。与传统的规则系统或监督学习模型相比，LLM 的核心优势在于其泛化能力：在未见过的任务类型、工具组合或失败模式上，LLM 可以基于上下文推理给出合理的建议。

然而，将 LLM 直接作为工作流的唯一决策者面临三个主要风险。第一是可靠性——LLM 的输出具有随机性，在需要确定性行为的关键节点（如安全判定、终态确认）上不能依赖概率性推断。第二是可审计性——LLM 的推理链通常以自然语言形式存在，难以结构化地追踪和复现。第三是角色边界——当 LLM 同时承担规划、执行、安全审查和汇总多个角色时，职责交叉可能导致越权行为（如安全审查者直接修改计划）。

本系统对 LLM 的使用遵循"能力借用、决策结构化"的原则：PlannerAgent 使用 LLM 生成候选工具链和解释文本，但候选的硬可行性过滤、评分排序和运行时重排由算法确定性规则完成；HITL 的人工确认通过结构化的 PendingAction/Decision 而非 LLM 对话完成；安全判定由 SafetyAgent 的规则化插件执行。这一设计使 LLM 的能力服务于系统的结构化控制，而非替代结构化控制。

### 2.2.2 多 Agent 协作模式

多 Agent 系统（Multi-Agent System, MAS）是 AI 领域的经典架构模式，通过将复杂任务分配给多个具有独立角色的 Agent 来降低系统复杂度、提高鲁棒性和可解释性。在科学工作流场景中，多 Agent 协作的优势尤为明显：蛋白质设计流程跨越多个专业领域（序列设计、结构预测、质量控制、安全评估），每个领域需要不同的知识、工具和判断标准，将这些功能分配给独立的 Agent 比构建一个"全能型"单体控制器更加易于设计、测试和维护。

多个已发表的框架展示了 LLM 驱动的 Agent 协作：LangGraph 通过有向图定义 Agent 之间的消息传递和状态管理；AutoGen 引入可对话的 Agent 角色和群组聊天接口；CrewAI 以角色-任务-工具的模式定义 Agent 职责。这些框架提供了通用的多 Agent 编排能力，但它们设计时面向的是对话和文本处理场景，缺乏对科学工作流特有的 FSM 控制、快照恢复和审计链的原生支持。

本系统采用了自定义的 Agent 协作模型：Workflow/FSM 是 Agent 调度的唯一来源（SSOT），四类 Agent（PlannerAgent、ExecutorAgent、SafetyAgent、SummarizerAgent）由 FSM 在固定的生命周期阶段激活，Agent 之间不进行临时的点对点通信。这种模式比通用的 Agent 对话框架更加约束，但它确保了在任何时刻只有一个 Agent 拥有执行权，避免了多 Agent 并发决策可能带来的状态不一致和审计链路断裂。

## 2.3 科学工作流的控制与恢复

### 2.3.1 工作流管理系统

科学工作流管理系统（Scientific Workflow Management System, SWMS）是分布式计算和 e-Science 领域的长期研究方向。Pegasus 支持在分布式资源（集群、云、网格）上调度 DAG 定义的计算流程。Kepler 提供可视化的 Actor-Oriented 模型构建工作流。Nextflow 以 DSL 定义流程，支持容器化执行、自动重试和多云环境部署，在生物信息学领域有广泛应用。

然而，传统 SWMS 的设计重心是资源调度和故障时的重启，而非工作流级的运行时决策。它们的"自适应"主要体现在检测节点故障后重新调度任务，而非根据中间结果的质量和意义调整后续计划。例如，如果 Nextflow 流程的一个步骤成功完成了计算但产出了低质量的中间结果，后续步骤会照常执行——SWMS 不知道"低质量"意味着什么，只能判断"完成"或"崩溃"。

本系统与 SWMS 的关键差异在于引入了语义级的运行时感知：StepResult 不仅报告成功或失败，还携带了 failure_type（区分可重试错误和结构性失败）、质量指标（pLDDT、QC pass/fail）、安全信号（warn/block）和运行时估计（p_success、budget_pressure）。这些信息使 CEBRA-WP 能够在 SWMS 的"重试"之上进行更细粒度的恢复决策——局部修补、后缀重规划或止损。

### 2.3.2 有限状态机在工作流中的应用

有限状态机（Finite State Machine, FSM）是描述系统行为的经典形式化模型。在科学工作流中，FSM 的主要作用是约束任务的合法状态序列，防止非法迁移和状态不一致。与事件驱动架构相比，FSM 的优势在于状态空间的显式性和可验证性——所有可能的转移路径在定义时就已经确定，任何不在集合中的迁移被自动拒绝。

本系统使用 FSM 控制任务生命周期，定义了从 CREATED 到终态（DONE、FAILED、CANCELLED）的 11 个状态，包括三个 WAITING_* 中间状态作为人工审查点。FSM 的终态不可变性和等待态前必须持久化的约束通过 `AGENT_CONTRACT.md` 写为系统不变性，由单元测试（TC-S05）验证。这些设计使 FSM 不仅是一个状态记录器，而是系统行为正确性的可验证保障。

### 2.3.3 信念状态与部分可观测决策

在规划和控制理论中，当环境不完全可观测时，决策者不应直接依赖瞬时观测，而应维护一个信念状态（belief-state）来总结所有历史观测蕴含的环境信息。这一思想源自部分可观测 Markov 决策过程（POMDP），后被广泛应用于机器人导航、对话管理和程序化交易等领域。

本系统面对的蛋白质设计工作流具有显著的部分可观测特征：一次工具调用失败无法直接揭示这是偶发噪声还是系统性偏离；中间产物的质量下降无法自动映射为"后续步骤全无价值"还是"只需局部调整"；预算消耗的加速可能是任务复杂度导致的不可避免开销，也可能是低效候选链的浪费。Lite belief-state 正是为了在这种不完全信息条件下提供结构化的估计——它不是完整 POMDP 的状态空间，而是对五个关键隐变量（p_success、p_structural_failure、recovery_margin、expected_remaining_cost、evidence_sufficiency）的有界估计，以此支撑继续、修补、重规划或止损的四选一决策。

### 2.3.4 人在环路的设计模式

人在环路（Human-in-the-Loop, HITL）在机器学习和交互系统领域有多种实现模式。在主动学习中，HITL 指人类标注者选择最具信息量的未标记样本。在对话系统中，HITL 指人工客服在自动化对话失败时接管。在可解释 AI 中，HITL 指人类对模型决策进行审查和修正。

科学工作流中的 HITL 需求与上述场景不同。蛋白质设计的关键决策——是否批准一个高成本的工具链、是否接受一个局部修补方案、是否在恢复余量耗尽时止损——需要的是**结构化的决策支持**，而非实时的交互对话或细粒度的标注。科研人员通常不会在任务运行期间实时监控，而是在系统暂停后批量审查。这意味着 HITL 机制需要具备三个关键能力：决策上下文能够在暂停期间持久化（快照）、审查信息包含可解释的依据（候选评分分解、运行时状态摘要、推荐理由）、决策后系统能够可靠地恢复执行（EventLog + FSM 迁移）。

本系统的 PendingAction/Decision 模型正是围绕这三个能力设计的。它不追求实时交互的流畅性，而是追求决策的可靠性和可审计性——决策一旦提交，事件日志即记录完整的 WAITING_ENTER → DECISION_APPLIED → WAITING_EXIT 审计链。

## 2.4 蛋白质设计核心工具

本节概述本系统通过 ToolAdapter 接入的主要蛋白质设计工具。详细的工具能力和 I/O 规格见 ProteinToolKG（`protein_tool_kg.json`）及第 5 章的工具适配器实现。

### 2.4.1 序列生成工具

**ProtGPT2** 是基于 GPT-2 架构的蛋白质序列语言模型，使用 UniRef50 数据库中的数百万条蛋白质序列进行自监督预训练。它能够根据提示序列或无条件生成类天然序列，在 de novo 设计中常用于序列探索阶段，产生多样化的候选序列空间。本系统中 ProtGPT2 通过远程 PLM REST 服务接入。

**ProteinMPNN** 是基于消息传递神经网络的逆向折叠模型，能够从给定的骨架三维坐标预测最优氨基酸序列。它的核心能力是"结构→序列"的逆向映射，在固定骨架上的序列设计和结构条件精修中具有广泛应用。本系统中 ProteinMPNN 支持本地推理。

### 2.4.2 结构预测工具

**AlphaFold2** 由 DeepMind 开发，通过多序列比对（MSA）、Evoformer 架构和结构模块实现原子级精度的蛋白质结构预测。其预测结果包含每个残基的 pLDDT 置信度分数。AlphaFold2 通常对具有丰富同源序列的天然蛋白质表现最佳，在 de novo 设计序列上的精度取决于序列与训练分布的接近程度。

**ESMFold** 由 Meta AI 开发，基于蛋白质语言模型 ESM-2 的内部表征直接进行结构预测，无需多序列比对。相比于 AlphaFold2，ESMFold 单序列预测速度快一个数量级，适合高通量的候选结构评估场景，但在部分 case 上的精度（尤其是侧链构象）低于 MSA 方法。本系统中 ESMFold 支持本地推理和 NIM 远程推理两种模式。

**OpenFold** 是 AlphaFold2 的开源再实现和优化版本，通过训练策略改进和工程优化在部分基准上接近或超越 AlphaFold2 的精度。在本系统中，结构预测步骤统一使用 OpenFold3 REST 远程服务（`execution_mode=openfold3_rest`），它封装了 OpenFold 的部署、序列化和结果归一化。

### 2.4.3 质量控制与目标评分工具

**BioPython QC** 是基于 BioPython 库的序列和结构质量控制工具。检查内容包括：序列合法性（仅含 20 种标准氨基酸）、序列长度是否符合约束范围、结构文件完整性、低复杂度区域占比和残基间冲突。该工具在质量门禁阶段用于快速过滤明显不可用的候选，避免在高代价步骤上浪费计算资源。

**DSSP**（Dictionary of Secondary Structure of Proteins）通过分析原子坐标来分配二级结构类型（alpha-螺旋、beta-折叠、转角等）。DSSP 的输出可用于验证设计的二级结构含量是否符合目标约束，也可作为后续目标评分的一个输入维度。

**Objective Ranker** 是本系统实现的目标评分工具，根据任务类型和证据来源对候选进行多目标排序。评分维度包括 generic_objective（通用目标匹配度）、stability（稳定性估计）、function（功能性指标）、novelty（与已知序列的差异度）和 structure_quality（结构质量）。证据可靠性权重（direct/proxy/degraded/missing）被编码到后验目标评分中（详见第 4 章 CEBRA-WP 算法描述），使缺少直接证据的候选在排序中受到合理的抑制。

## 2.5 本章小结

本章从蛋白质计算设计的基础概念出发，概述了 de novo 设计的六阶段流程、LLM Agent 协作范式、科学工作流的状态管理与恢复理论，以及本系统涉及的蛋白质设计核心工具。这些技术背景为后续各章的系统需求分析、架构设计、实现描述和实验评估提供了术语基础和上下文锚点。第 3 章将从蛋白质设计工作流的实际问题出发，详细分析系统的功能需求和非功能约束。
