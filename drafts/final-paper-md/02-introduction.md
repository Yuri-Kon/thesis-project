# 第一章 绪论

## 1.1 研究背景

蛋白质是生命活动中的核心执行分子，其功能通常取决于三维结构和局部相互作用模式，而这些结构特征又受到氨基酸序列、环境条件和分子间作用的共同影响。蛋白质计算设计的目标，是在给定结构、稳定性、功能或其他属性要求的前提下生成或筛选候选序列。近年来，深度学习方法推动了结构预测和序列设计的发展：AlphaFold 系列工作提高了蛋白质结构预测精度[@jumper2021alphafold]，RFdiffusion 等方法展示了从结构生成角度开展 de novo 设计的能力[@watson2023rfdiffusion]，ProteinMPNN、ESMFold、ProtGPT2 等工具也分别在逆向折叠、快速结构预测和序列生成方面形成了可复用能力。

但是，单个模型或工具能力的提升，并不意味着完整设计流程已经自动化。一次实际的计算设计任务往往包括目标理解、序列生成、结构预测、质量控制、目标评分和结果汇总等环节。不同工具在输入输出格式、运行成本、失败模式和适用边界上差异明显：序列生成工具可以扩展候选空间，结构预测工具通常成本更高，质量门禁和目标评分工具则需要随任务目标选择指标。如果系统在任务开始时固定一条工具链并顺序执行，那么当中间结果质量不足、高代价工具调用失败、预算压力升高或安全风险出现时，系统就难以及时依据运行时证据调整后续计划。

与此同时，大语言模型 Agent（Large Language Model Agent，LLM Agent）为复杂任务自动化提供了新的交互和规划方式。ReAct 将推理与行动结合，使模型能够在环境反馈中逐步执行任务[@yao2022react]；Toolformer 等工作则表明，“何时调用工具”可以成为语言模型能力的一部分[@schick2023toolformer]。这些研究为自然语言目标解析、工具选择和过程解释提供了启发。蛋白质设计属于高成本、长链路、强约束的科研工作流，仅依靠一次性语言模型规划，仍难以保证计划可执行、过程可恢复、结果可审计。因此，系统还需要在 LLM Agent 的候选生成能力之外，引入明确的状态控制、工具约束、人工确认和运行时恢复机制。

基于上述背景，本文不重新训练蛋白质生成模型，也不替代 AlphaFold、ESMFold、ProteinMPNN 等已有工具，而是研究如何把异构蛋白质设计工具组织为可规划、可执行、可恢复和可审计的工作流系统。该问题同时具有软件工程和算法控制属性：自然语言目标需要收敛为结构化任务，候选工作流需要依据面向蛋白质设计的工具知识图谱（ProteinToolKG）生成，高风险节点需要引入人在环决策（Human-in-the-loop，HITL），失败后需要保留有效前缀并执行局部修补或后缀重规划，运行过程也需要沉淀为可复核的日志、快照和实验数据。

## 1.2 研究问题与挑战

面向 de novo 蛋白质设计的工作流自动化至少面临以下四类挑战。

其一，工具链组合具有异构性和约束性。蛋白质设计任务可能同时涉及序列生成、结构预测、结构质量检查、二级结构分析、相似性检索和多目标评分。不同工具的输入字段、输出字段、执行模式、成本等级和安全边界并不一致。缺少统一的工具能力描述和输入输出约束检查时，自动生成的计划容易出现工具不存在、schema 不合法、步骤引用不闭合或预算超限等问题。

其二，执行过程具有部分可观测性。系统在某个时间点只能看到当前步骤结果、错误信息、质量指标和预算消耗，无法直接判断后续工作流是否仍然值得继续。例如，结构预测失败可能来自远程服务暂时异常，也可能说明上游候选序列质量不足；质量门禁失败可能通过参数修补恢复，也可能要求替换未执行后缀。缺少运行时状态估计时，系统容易在“继续执行”和“直接失败”之间作出过于粗略的选择。

其三，高代价步骤需要可解释的决策边界。结构预测、结构条件精修和复杂目标评分往往比基础质量检查具有更高计算成本。证据不足时过早进入高代价步骤，会增加无效调用；过度保守又可能阻碍任务推进。因此，候选评分需要同时考虑目标匹配、成本、风险、证据充分度和恢复余量。

其四，科研工作流需要可追溯和可恢复。蛋白质设计任务的中间结果本身具有价值，后续步骤失败不应自动否定此前完成的序列生成、质量检查或结构预测结果。系统需要记录事件日志、任务快照、人工决策和恢复历史，使任务能够在等待人工确认或服务中断后恢复上下文，也使后续实验分析能够追踪结果来源。

由此可见，本文需要解决的是一个工作流层面的规划与控制问题：如何在已有蛋白质设计工具之上构建一个能够理解任务约束、生成候选工具链、根据运行时证据调整计划，并在失败后进行可审计恢复的系统。

## 1.3 研究目标

本文的研究目标是设计并实现一个面向 de novo 蛋白质设计的多 Agent 协作与自适应工作流规划系统。系统接收自然语言目标和结构化约束，输出候选序列、结构产物、质量指标、风险标记和报告，并在执行过程中提供候选计划生成、工具调用、HITL 确认、运行时恢复和审计追踪能力。

围绕这一总体目标，本文设置以下具体目标。

第一，构建面向蛋白质设计工具链的统一任务和工具表示。系统将用户目标、任务约束、工具能力、输入输出字段、成本和安全等级纳入结构化契约，使 Planner 能够生成可解释候选，Executor 能够按统一接口调用工具。

第二，设计受控的多 Agent 工作流架构。PlannerAgent、ExecutorAgent、SafetyAgent 和 SummarizerAgent 需要拥有明确职责边界，避免一个组件同时承担计划、执行、安全审查和结果汇总。任务状态应由有限状态机（Finite State Machine，FSM）统一控制，HITL 应通过结构化 PendingAction 和 Decision 接入。

第三，提出面向高代价科研工作流的约束与证据感知、信念引导、恢复自适应工作流规划（Constraint- and Evidence-aware Belief-guided Recovery-adaptive Workflow Planning，CEBRA-WP）算法。算法需要综合约束、证据、Lite belief-state / 轻量信念状态和恢复动作效用，对候选工作流进行生成、过滤、评分、运行时重排序和恢复动作选择。算法的目标不是替代底层蛋白质设计算法，而是在工作流层降低无效高代价调用并提升恢复过程的可解释性。

第四，完成系统原型实现和验证。系统提供后端 API、前端工作台、工作流运行时、工具适配器、事件日志和快照机制，并通过系统测试、功能验证和策略对照实验评估其可执行性、可追溯性和机制有效性。

## 1.4 主要工作

本文围绕上述目标完成了以下工作。

（1）设计了面向蛋白质设计工作流的五层系统架构。该架构分离输入交互、智能规划、工作流执行、安全汇总和资源管理，通过 FSM 约束任务生命周期，通过 PendingAction/Decision 实现 HITL，并通过 ToolAdapter 和 ProteinToolKG 连接异构工具能力。

（2）提出了 CEBRA-WP 工作流规划算法。该算法以目标 `g`、约束集合 `C`、ProteinToolKG `K`、历史 `h_t`、观测 `o_t` 和 Lite belief-state / 轻量信念状态 `x_t` 为输入，经过候选生成、硬可行性过滤、静态评分、后验目标评分、运行时重排序和恢复动作选择，输出候选集合、默认建议和恢复动作。算法支持 `continue`、`patch_local`、`suffix_replan` 和 `stop` 四类动作，并将 `stop` 映射为受 FSM 和 HITL 约束的终止型重规划候选。

（3）实现了前后端系统原型。后端采用 Python、FastAPI 和 Pydantic 实现任务接入、计划生成、工作流执行、HITL 接口、事件查询和报告读取；前端采用 React、TypeScript 和 Vite 构建轻量 Web 工作台；工具层通过统一适配器封装 ProtGPT2、ProteinMPNN、ESMFold/OpenFold、Biopython QC、DSSP 和目标评分等能力。

（4）完成了系统测试与策略对照实验。系统测试覆盖 API 合约、数据契约、FSM 迁移、HITL 决策边界、快照恢复、前端与 CLI 可用性、安全阻断和恢复路径。策略实验围绕 `static_top1`、`fixed_threshold_gate`、`dynamic_no_belief_state` 和 `lite_belief_state` 四组配置展开，分析 CEBRA-WP 在机制可观测性、成本控制和恢复决策方面的作用。

## 1.5 论文结构

本文共八章，组织结构如下。

第一章为绪论，介绍研究背景、问题挑战、研究目标、主要工作和论文结构。

第二章为相关技术与理论基础，梳理蛋白质设计工具、科学工作流、大语言模型 Agent、部分可观测规划和预算感知决策等基础内容。

第三章为需求分析，从用户场景、功能需求、非功能需求和问题-方案对应关系出发，明确系统需要支持的任务接入、候选生成、工作流执行、HITL、运行时恢复和审计追踪能力。

第四章为系统设计，说明系统五层架构、核心组件、有限状态机、六阶段蛋白质设计工作流、核心数据契约和 CEBRA-WP 算法定义。

第五章为系统实现，介绍后端 API、前端工作台、工作流运行时、RuntimeState 更新、RuntimeEvaluator、工具适配器和 ProteinToolKG 等工程实现。

第六章为系统测试与验证，报告系统测试用例、验证证据、API 与前端可用性、恢复边界和安全边界验证结果。

第七章为实验与结果分析，给出四组策略对照实验的设计、指标、结果表格和案例分析，讨论 CEBRA-WP 的机制可行性和限制。

第八章为总结与展望，总结本文工作、主要贡献、当前限制和后续研究方向。
