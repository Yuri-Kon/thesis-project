# 第三轮语言精修记录

本轮目标是降低重复表达和模板化痕迹，提升论文语言的自然度、学术规范性和段落衔接质量。修改范围限定为语言润色、句式重组、逻辑衔接优化和表达规范化；未新增未经来源支持的事实、数据、观点或案例，未改变章节结构、图表编号、参考文献引用和实验结论。

## 1. 总体修改建议

1. 继续保留“研究边界”类表达。正文中少量“不是……而是……”用于区分本文与底层蛋白质模型、湿实验验证和外部流程引擎之间的关系，属于必要边界说明，不建议全部删除。
2. 后续终稿排版前，可再次压缩第五章算法解释和第八章总结展望中的长句。这些段落事实密度较高，本轮已做轻量拆分，但最终 Word/LaTeX 版中仍可结合版面继续微调。
3. 图表、代码清单和公式周围的解释文字应保持稳定，不建议为了降重改动符号、变量名、指标名和实验数值。
4. 对“实验支持”“验证结果表明”等判断性表达，应继续保留“本文测试范围内”“当前实验矩阵中”“原型层面”等限定词，避免扩大结论。

## 2. 修改后文本摘录

### 2.1 第一章绪论

原背景段存在信息密度较高、多个工具并列堆叠的问题，已调整为更自然的递进表达：

> 蛋白质是生命活动中的核心执行分子，其功能通常取决于三维结构和局部相互作用模式，而这些结构特征又受到氨基酸序列、环境条件和分子间作用的共同影响。蛋白质计算设计的目标，是在给定结构、稳定性、功能或其他属性要求的前提下生成或筛选候选序列。

研究定位段已改为先承接背景，再说明论文关注点：

> 基于上述背景，本文不重新训练蛋白质生成模型，也不替代 AlphaFold、ESMFold、ProteinMPNN 等已有工具，而是研究如何把异构蛋白质设计工具组织为可规划、可执行、可恢复和可审计的工作流系统。

### 2.2 第二章相关技术

六阶段流程原先按“第一阶段、第二阶段……”展开，句式较机械；本轮改为并列解释：

> 本文采用六阶段能力分层理解 de novo 设计流程：序列探索用于生成候选序列；结构映射用于预测候选序列可能折叠出的三维结构；质量门禁用于剔除长度、残基合法性、低复杂度或结构完整性不满足要求的候选；结构条件精修依据结构反馈重新设计序列；目标评分综合稳定性、结构质量、novelty 和任务目标匹配度对候选排序；结果汇总则生成面向科研人员复核的报告。

### 2.3 第四章系统设计

系统设计章首已从“需求复述”调整为“设计问题收束”：

> 前一章已经指出，蛋白质设计任务通常存在输入不完整、工具链多阶段依赖、高代价结构预测与目标评分不宜盲目调用、执行失败后仍需保留已有证据等特点。因此，本文系统设计的重点不是把若干工具串接成固定流水线，而是在可执行约束、安全约束和预算约束下，为蛋白质设计任务提供可规划、可恢复、可审计的工作流运行框架。

算法定义中的边界说明已合并为更紧凑的表达：

> 该定义突出两点：一是候选生成与候选选择相互分离，Planner 可以生成多个方案，但只有通过可行性和效用评估的候选才会进入执行或人工确认；二是运行时状态只修正排序和动作建议，不改变 FSM、Agent 职责和硬约束。

### 2.4 第五章系统实现

实现章开头已减少“本文系统”的重复：

> 本章在第四章系统设计的基础上，说明本文系统的工程实现方式。系统实现的目标不是重新实现蛋白质结构预测或序列设计模型，而是在已有蛋白质设计工具和远程模型服务之上，构建能够完成任务接入、候选计划生成、HITL 确认、工具执行、运行时恢复和结果审计的工作流控制系统。

HITL 接口段已将“前端临时状态”改为更规范的系统边界说明：

> 这一过程保证人工决策属于工作流状态，而不是前端临时 UI 状态。

### 2.5 第六章系统测试

章节开头已拆分过长说明，使“本章”和“第七章”的关系更清晰：

> 与第七章的策略对比实验不同，本章关注系统是否按照第四章定义的架构、状态机、HITL 机制、工具适配机制和恢复机制正确运行。换言之，本章先验证“系统能否可靠地承载实验”，第七章再讨论不同规划策略在该系统上的效果差异。

CLI 限制已改为直接说明，不再使用“不要扩大为……”式表达：

> 部分通过项为 CLI 可用性验证：`intake schema` 和 `task show` 等核心命令可用，`timeline show` 与 `report show` 当前仍输出 usage 提示，因此在终稿中作为实现限制说明。

### 2.6 第七章实验分析

主结果解释由“显示出三个结果”改为更自然的“主要现象”：

> 表 7-2 显示出三个主要现象。static_top1 在该矩阵中成功率最高，提示任务集中的多数初始候选已经具备较强可执行性。fixed_threshold_gate 是唯一触发真实局部修补的组，平均局部修补次数为 0.2857，同时高代价调用总数升至 28。lite_belief_state 是唯一 runtime_state_observable_rate 为 1.0000 的组，说明其 Lite belief-state / 轻量信念状态链路在所有 run 中均产生可追踪输出。

章节结论已保留数据和边界，但减少了机械编号感：

> 首先，在当前实验矩阵中，CEBRA-WP 的机制链路可执行、可追踪，lite_belief_state 组 21/21 runs 产生 RuntimeState，runtime_state_observable_rate 为 1.0000。其次，fixed_threshold_gate 触发 6 次真实局部修补，高代价调用总数达到 28，说明固定阈值门控能够暴露恢复需求，也会带来额外执行成本。

### 2.7 第八章总结与展望

结论章贡献表述已弱化口号式总结：

> 基于这些结果，本文将算法贡献限定在高代价工作流中的恢复控制、成本意识和审计解释，而不是单纯以成功率作为评价依据。

未来工作中的工程化表述已改为更审慎的“有助于”：

> 这些改进有助于提升系统在真实科研工作流中的可维护性和长期运行能力。
