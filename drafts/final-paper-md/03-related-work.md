# 第二章 相关技术与理论基础

绪论已经从课题背景、蛋白质设计技术发展、MDP/POMDP 与 Agent 协作理论等角度说明了本文选题的来源。本章转向技术与理论基础的界定，重点解释后续章节反复使用的概念、工具能力和工作流控制依据。由于本文工作位于蛋白质计算设计、科学工作流、大语言模型 Agent 和运行时恢复控制的交叉处，本章围绕“如何将已有工具组织成可控工作流”展开。

## 2.1 蛋白质计算设计基础

蛋白质由氨基酸序列组成，并在特定条件下折叠为三维结构。通常认为，序列、结构和功能之间存在层级关系：序列影响折叠构象，结构进一步影响结合、催化、稳定性和其他功能属性。蛋白质设计的目标是在给定结构、功能或属性约束下寻找合适序列；de novo 蛋白质设计则进一步强调不直接依赖天然模板，从目标条件出发生成新的候选序列或结构。面向本文系统，蛋白质设计还需要被理解为可拆分、可组合、可恢复的任务过程。

该问题具有高维组合搜索特征。长度为 `n` 的蛋白质序列理论空间为 `20^n`，即使实际搜索会受到物理、进化和任务约束限制，候选空间仍远超人工枚举能力。因此，现代蛋白质设计通常将生成、预测、筛选和评分拆分为多个阶段，通过工具链逐步缩小候选空间。

本文采用六阶段能力分层理解 de novo 设计流程：序列探索用于生成候选序列；结构映射用于预测候选序列可能折叠出的三维结构；质量门禁用于剔除长度、残基合法性、低复杂度或结构完整性不满足要求的候选；结构条件精修依据结构反馈重新设计序列；目标评分综合稳定性、结构质量、novelty 和任务目标匹配度对候选排序；结果汇总则生成面向科研人员复核的报告。

这六个阶段不是固定流水线，而是可组合的能力单元。实际任务可能跳过部分阶段，也可能在结构预测与结构条件精修之间迭代。第四章将基于这一能力分层设计系统工作流。

## 2.2 蛋白质设计与分析工具

深度学习和生物信息学工具为本文系统提供底层能力来源。这里按照系统集成视角对工具能力进行归类，说明它们在本文工作流中的角色。

AlphaFold2 显著提升了蛋白质结构预测精度，成为结构预测领域的重要基准[@jumper2021alphafold]。AlphaFold3 进一步扩展到更复杂的生物分子相互作用结构预测场景[@abramson2024alphafold3]。OpenFold 是 AlphaFold2 的开源实现与工程化再训练版本，为结构预测工具接入提供了可部署基础[@ahdritz2024openfold]。ESMFold 利用蛋白质语言模型表征进行快速结构预测，在速度和部署便利性方面具有优势[@lin2023esmfold]。

在序列设计和生成方面，ProteinMPNN 使用深度学习方法从蛋白质骨架结构反推氨基酸序列，适合结构条件下的逆向折叠任务[@dauparas2022proteinmpnn]。ProtGPT2 则以蛋白质语言模型方式生成类天然序列，可用于候选序列探索[@ferruz2022protgpt2]。RFdiffusion 从扩散生成角度推动 de novo 结构与功能设计，为生成式蛋白质设计提供了重要背景[@watson2023rfdiffusion]。

传统平台和基础库同样重要。Rosetta3 长期支持基于物理能量函数的蛋白质建模与设计，是传统蛋白质设计平台的代表[@leaverfay2011rosetta3]。Biopython 为序列解析、结构文件处理和基础生物信息学操作提供了稳定接口[@cock2009biopython]。

这些工具各有优势，但单个工具并不会自动解决跨工具编排问题。结构预测工具关注预测精度，序列设计工具关注候选生成，基础库侧重数据处理。本文系统将这些能力通过 ToolAdapter 和 ProteinToolKG 组织为可组合工具链，并在运行时根据证据、成本和风险选择后续动作。

## 2.3 科学工作流与可复现执行

科学工作流管理系统（Scientific Workflow Management System，SWMS）用于组织复杂计算流程、管理数据依赖、调度任务并记录执行过程。蛋白质设计需要可追踪、可恢复的工作流支撑，因此有必要先明确通用科学工作流系统能够提供的基础能力，以及本文为何没有直接将全局控制流交给通用流程引擎。Pegasus 支持将抽象工作流映射到分布式资源，强调工作流计划、调度和可复现执行[@deelman2005pegasus]。Nextflow 以 DSL 描述计算流程，支持容器化、任务缓存和可复现运行，在生物信息学流程中应用广泛[@ditommaso2017nextflow]。

科学工作流系统擅长稳定执行预定义流程并管理计算资源。本文场景中的核心问题不仅是“如何运行一个已定义 DAG”，还包括“何时应改变后续计划”。例如，某个步骤虽然成功执行，但产物质量不足，传统工作流系统通常只能记录步骤完成，难以判断该质量信号对后续蛋白质设计目标的影响。高代价工具失败时，传统恢复也多集中在重试或重新调度，不一定能够判断是否应保留已完成前缀并替换未执行后缀。

因此，本文没有把全局控制流交给外部流程引擎，而是使用自定义 Workflow/FSM 管理任务生命周期。外部工具或流程后端可作为单个 PlanStep 的执行方式接入，但任务创建、候选确认、运行时恢复、HITL（人在环决策）和审计链路由系统自身控制。该选择并不否定科学工作流系统的价值，而是将其定位于执行资源层或单步工具后端，将语义级恢复控制保留在本文系统中。

## 2.4 大语言模型 Agent 与工具调用

大语言模型（Large Language Model，LLM）在自然语言理解、任务分解和工具使用方面表现出较强能力。在本文系统中，LLM Agent 主要承担自然语言入口、候选生成和过程解释等职责。ReAct 将推理与行动结合，使模型能够在外部环境反馈下交替进行思考和工具调用[@yao2022react]。Toolformer 从模型学习角度说明语言模型可以学习在合适时机调用外部工具[@schick2023toolformer]。Tree of Thoughts 强调保留多个候选推理路径并进行搜索，有助于复杂问题求解[@yao2023tot]。Reflexion 则利用失败反馈和自我反思改善后续任务表现[@shinn2023reflexion]。

这些研究为本文的候选生成、工具调用和失败反馈机制提供了启发。不过，蛋白质设计工作流不同于一般文本任务：工具调用具有真实计算成本，输出需要满足严格 schema，安全风险和预算约束不能只依赖自然语言判断，任务状态也需要在系统重启和人工等待期间保持一致。OSWorld 等开放环境 Agent 评测工作也提示，Agent 的执行能力、环境稳健性和恢复能力应被显式评估，而不能只评价最终文本输出[@xie2024osworld]。

本文系统采用多 Agent 职责划分：PlannerAgent 生成候选工具链和解释，ExecutorAgent 调用已确认的工具步骤，SafetyAgent 提供风险信号，SummarizerAgent 汇总最终结果。LLM 可参与候选生成和解释，但候选硬可行性过滤、FSM 状态迁移、HITL 决策应用和运行时恢复动作由结构化算法和系统契约控制。这样可以把 LLM 能力嵌入工作流，而不是让 LLM 独占控制权。

## 2.5 部分可观测规划与预算感知决策

MDP/POMDP 为本文理解运行时恢复提供了理论参照，但本文只借鉴部分可观测决策思想，不求解完整 POMDP。具体到系统执行过程，系统能够观察到步骤成功或失败、错误类型、结构质量指标、安全信号和预算消耗，却无法直接知道当前工具链是否仍然具有全局成功可能，也无法直接区分偶发失败和结构性失败。因此，瞬时观测不足以支持可靠决策。

部分可观测规划研究认为，在环境状态不能被完全观测时，决策者需要维护 belief-state，以历史观测的摘要形式估计当前状态[@kaelbling1998pomdp]。后续部分可观测启发式规划研究进一步强调，启发式函数应考虑随机效应与信息价值[@shani2024heuristics]。本文并不求解完整 POMDP，而是将这一思想工程化为 Lite belief-state / 轻量信念状态：使用 $p_{\mathrm{succ}}$、$p_{\mathrm{sf}}$、$r_{\mathrm{rec}}$、$c_{\mathrm{rem}}$ 和 $e_{\mathrm{suf}}$ 五个变量描述运行时状态。

预算约束同样是高代价科研工作流的重要因素。预算强化学习研究说明，资源消耗和风险约束应被纳入决策目标，而不是在任务结束后再统计[@carrara2019budgetedrl]。在本文场景中，这一思想体现为 CEBRA-WP 对 $c_{\mathrm{rem}}$、$b_{\mathrm{press}}$ 和高代价调用的显式建模。系统在证据不足时降低高成本候选的排序，在局部失败后优先判断能否通过 `patch_local`（局部修补）保留有效前缀，在恢复余量不足时生成受控的 `stop`（终止型重规划候选）。

## 2.6 相关系统与本文定位

近期蛋白质设计相关预印本中已有工作开始关注多目标搜索、属性引导和系统化设计流程。例如，RosettaSearch 关注蛋白质序列设计中的推理时多目标搜索[@rosettasearch2026]，AutoBinder Agent 探索面向 binder 设计的端到端 Agent 系统[@autobinder2026]，property-driven inverse folding 相关工作则讨论多目标偏好与 developability 约束[@preferenceinversefolding2026]。这些相关预印本提示，蛋白质设计正在从单模型预测走向多目标、多工具和系统化流程。

本文与这些工作的侧重点不同。本文不提出新的蛋白质生成模型，也不声称在湿实验层面验证设计蛋白功能，而是关注工作流控制层问题：如何在已有工具之上组织候选工作流，如何用 ProteinToolKG 约束工具链生成，如何用 Lite belief-state / 轻量信念状态进行运行时重排序，以及如何在失败、风险和预算压力下进行可审计恢复。因此，本文的贡献主要体现为系统架构、工作流规划算法和工程验证，而不是底层蛋白质模型本身。

## 2.7 本章小结

本章界定了后续系统设计中需要使用的主要技术概念。已有蛋白质工具为序列生成、结构预测和质量评估提供能力来源；科学工作流系统为可复现执行提供基础思想；LLM Agent 研究为任务分解、工具调用和失败反馈提供方法参照；部分可观测规划和预算感知决策则支撑运行时恢复控制。这些基础共同指向一个判断：本文系统需求并非单一工具能力需求，而是跨工具编排、运行时控制和证据追踪的综合需求。下一章将在这些概念界定之上分析系统的具体需求。
