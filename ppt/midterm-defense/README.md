# 中期答辩 PPT 制作指南

适用对象：`基于大模型驱动的 Agent 协作新一代蛋白质设计系统开发` 中期答辩  
使用范围：本指南用于组织中期答辩 PPT 的章节、页面、配图与讲述重点。  
当前阶段说明：本版已经把实验部分改写为 `中期机制验证基准` 口径，并把新的图表复制到 `assets/benchmark/`。  
关于界面截图和实验流程截图，后续再单独补充。

## 1. 总体制作原则

- 这次汇报的重点不是完整论文，而是讲清楚“目前做到什么、怎么证明、后面还差什么”。
- 整体表述建议保持为：`系统主链已实现，关键机制已通过可复现实验验证，生物效果类结果仍在后续阶段继续补强`。
- 不要再把实验部分写成“当前纵向效果很好”，因为旧数据说服力不足；应转为强调系统在门控、HITL、恢复、路由、汇总和证据沉淀方面已经形成稳定闭环。
- 每页只保留 `3~5` 个重点，优先放图、流程和简明结论，不要大段抄报告原文。
- 7 分钟答辩建议控制在 `7` 页左右，结构上严格对应以下五章：
  - 预定的执行计划
  - 已完成工作
  - 实验案例
  - 后期计划
  - 困难与按时完成的可能性

## 2. 推荐总页数与章节映射

建议页数：`7` 页

1. 封面
2. 预定的执行计划
3. 已完成工作
4. 实验案例一：人工确认与失败后恢复流程
5. 实验案例二：中期机制验证基准结果
6. 后期计划
7. 困难与按时完成的可能性

说明：

- 如果老师习惯先看目录，可以在封面后增加目录页，但 7 分钟以内一般可以省略。
- 当前阶段不建议单独拆出“相关工作”或“研究背景”页面，否则会占用进度汇报时间。

### 第 2 页：预定的执行计划

这一页对应章节：`预定的执行计划`

#### 页面标题建议

`预定执行计划与当前推进情况`

#### 推荐版式

- 左侧：三阶段时间线
- 右侧：当前状态总结

#### 页面应写入的主要内容

第一阶段：`2025.12 - 2026.01`

- 搭好系统骨架
- 重点说明：先把任务的几个阶段定义清楚，例如“创建任务、规划步骤、等待人工确认、正式执行、生成总结”

第二阶段：`2026.01 - 2026.03 上旬`

- 补齐系统主流程
- 重点说明：让系统能够从用户目标出发，生成方案、调用工具、在失败后修补或重新规划，并完成从头设计流程中的几个主要步骤

第三阶段：`2026.03 中旬至今`

- 开始整理中期实验、过程记录和论文材料
- 实验主线已经从“纵向效果对比”调整为“机制验证 + 证据闭环展示”

右侧状态建议写为：

- 主流程：已完成
- 人工确认流程：已完成
- 出错后恢复流程：已完成
- 中期机制验证基准：已完成
- 横向对比实验：进行中
- 外部模型训练：未开始

#### 本页结论句建议

`截至中期，项目整体按照“先搭系统骨架，再打通完整流程，最后补实验和论文材料”的顺序推进，整体路线没有偏离。`

#### 建议使用的图示类型

- 自制时间线图
- 不建议用截图

#### 内容来源

- `paper/tex/chapters-midterm/02-progress.tex`
- `paper/tex/chapters-midterm/03-next-step.tex`

#### 制作注意事项

- 不要直接截图 LaTeX 表格。
- 把表格内容改写成三段时间线，更容易让老师听懂。

### 第 4 页：实验案例一

这一页对应章节：`实验案例`

#### 页面标题建议

`实验案例一：人工确认与失败后恢复流程`

#### 本页要表达的重点

- 系统不是一条路跑到底，而是能在关键位置停下来等人确认。
- 人工确认之后，系统还能继续往后跑，而不是中断。
- 如果执行过程出错，系统也不是直接失败，而是会尝试修补或重新安排后续步骤。

#### 页面应写入的主要内容

- 系统会在关键节点进入“等待人工确认”的状态。
- 人工的选择会被记录下来，而不是只停留在界面点击层面。
- 系统在收到确认后，可以继续执行，并最终完成任务。
- 在恢复场景中，系统支持从参数修补升级到工具替换，再升级到 replan。

#### 最适合使用的图示

优先使用：

- `assets/recovery-hitl-overview.pdf`
- `assets/total-sequence.svg`
- 可选补充：`assets/single-step-sequence.svg`

如果只放一个图，优先使用：

- `assets/recovery-hitl-overview.pdf`

可以在图旁边单独补一张简化流程图：

`执行中 -> 暂停等待人工确认 -> 人工同意 -> 局部修补 / 工具替换 -> 继续执行 -> 完成`

### 第 5 页：实验案例二

这一页对应章节：`实验案例`

#### 页面标题建议

`实验案例二：中期机制验证基准结果`

#### 为什么改成这组实验

- 旧的纵向实验结果很难支撑“方法效果显著提升”的说法。
- 当前系统最成熟、最有说服力的成果，其实是“控制能力、恢复能力和可审计性已经稳定成立”。
- 因此中期答辩更适合使用 `机制验证基准` 作为主实验结果页。

#### 页面应写入的主要内容

建议正文直接写这 4 条：

- 新基准共包含 `17` 个可复现场景，覆盖 `5` 个实验家族。
- 家族层面全部通过：Execution & Summary `3/3`，Gate `2/2`，HITL & Audit `4/4`，Planner Routing `3/3`，Recovery `5/5`。
- 证据文件完整率为 `100%`：`event_log 6/6`，`snapshot 2/2`，`report 3/3`。
- 关键机制覆盖也达到 `100%`，其中 `event_audit 7/7`、`patch_recovery 6/6`、`planner_routing 3/3`、`replan_escalation 3/3`、`result_summarization 3/3`。

#### 推荐图表摆放方式

主图优先级：

1. `assets/benchmark/family_summary.svg`
2. `assets/benchmark/capability_coverage.svg`
3. `assets/benchmark/artifact_support.svg`

推荐版式：

- 主图：`family_summary.svg`
- 右下角小图：`artifact_support.svg`
- 如果一页能放两张图，再加 `capability_coverage.svg`

#### 图表讲法建议

- `family_summary.svg`：强调系统不是只有一个 demo，而是已经形成覆盖多个机制家族的稳定验证集。
- `capability_coverage.svg`：强调门控、HITL、恢复、路由、汇总这些核心能力都已经被验证。
- `artifact_support.svg`：强调不只是“测试通过”，而且日志、快照、报告文件也都落盘，适合作为答辩证据。

#### 本页结论句建议

`因此，本次中期实验页的重点不再是证明最终生物效果已经最优，而是证明系统关键机制已经形成稳定、可复现、可审计的工程闭环。`

#### 当前图表来源

- `assets/benchmark/family_summary.svg`
- `assets/benchmark/capability_coverage.svg`
- `assets/benchmark/artifact_support.svg`
- `assets/benchmark/midterm_mechanism_benchmark_report.md`

#### 制作注意事项

- 这页不要再放旧的 A0-A6 成功率全 0 的表。
- 如需提及旧实验，只能作为“原有结果说服力不足，因此本次中期答辩改用机制验证基准作为主结果页”的背景说明。

### 第 7 页：困难与按时完成的可能性

这一页对应章节：`困难与按时完成的可能性`

#### 页面标题建议

`存在的困难与按时完成的可能性`

#### 推荐版式

- 左侧：困难
- 右侧：可行性判断

#### 左侧应写入的困难

- 横向对比实验尚未完成。
- 统一评估口径和图表结果仍需继续收口。
- 外部模型专用训练尚未启动。
- 多工具真实运行受远程平台和资源条件影响。
- 工程材料向论文表达的转写仍需继续整理。

#### 右侧应写入的判断

- 当前软件项目研发约完成 `80%`。
- 系统主体、关键控制机制、主要运行链路已经基本完成。
- 现在已经额外形成了一套中期机制验证基准，能更稳定地支撑答辩展示。
- 剩余工作边界清楚，主要属于实验补齐、评估收口和论文整理。
- 总体判断：`具备按时完成论文与参加答辩的现实基础`。

#### 建议使用的图示

- 自制“风险与可行性对照信息图”
