# 中期答辩 PPT 制作指南

适用对象：`基于大模型驱动的 Agent 协作新一代蛋白质设计系统开发` 中期答辩  
使用范围：本指南用于组织中期答辩 PPT 的章节、页面、配图与讲述重点。  
当前阶段说明：本版已经把实验部分改写为 `中期机制验证基准` 口径，并把新的图表复制到 `assets/benchmark/`。  
关于界面截图和实验流程截图，后续再单独补充。

## 1. 总体制作原则

- 这次汇报的重点不是完整论文，而是讲清楚“目前做到什么、怎么证明、后面还差什么”。
- 整体表述建议保持为：`系统主链已实现，关键机制已通过可复现实验验证，生物效果类结果仍在后续阶段继续补强`。
- 不要再把实验部分写成“当前纵向效果很好”，因为旧数据说服力不足；应转为强调系统在门控、HITL、恢复、路由、汇总和证据沉淀方面已经形成稳定闭环。
- 每页只保留 `3~5` 个重点，优先放图、流程和简明结论，不要大段抄报告原文。
- 7 分钟答辩建议控制在 `8~9` 页左右，但每页必须只保留核心信息，结构上严格对应以下五章：
  - 预定的执行计划
  - 已完成工作
  - 实验案例
  - 后期计划
  - 困难与按时完成的可能性

## 2. 推荐总页数与章节映射

建议页数：`8~9` 页

1. 封面
2. 预定的执行计划
3. 已完成工作（一）：系统骨架与角色分工
4. 已完成工作（二）：关键运行机制
5. 已完成工作（三）：工程证据与可展示产物
6. 实验案例一：人工确认与失败后恢复流程
7. 实验案例二：中期机制验证基准结果
8. 后期计划
9. 困难与按时完成的可能性

说明：

- 如果老师习惯先看目录，可以在封面后增加目录页，但 7 分钟以内一般可以省略。
- 当前阶段不建议单独拆出“相关工作”或“研究背景”页面，否则会占用进度汇报时间。
- 第二章“已完成工作”建议拆成 `2~3` 页，否则一页里同时塞系统骨架、运行机制和证据产物，会明显过满。

### 第 6 页：实验案例一

这一页对应章节：`实验案例`

#### 页面标题建议

`实验案例一：人工确认与失败恢复案例回放`

#### 本页实验定位

- 这一页属于 `机制案例回放`，用于展示系统在单个代表性流程中的行为。
- 这一页不是统计结果页，因此不要把它表述成“实验显著优于基线”。
- 本页最重要的是讲清楚：系统如何进入等待态、如何接收人工决策、如何在失败后恢复并继续执行。

#### 本页要表达的重点

- 系统不是一条路跑到底，而是能在关键位置停下来等人确认。
- 人工确认之后，系统还能继续往后跑，而不是中断。
- 如果执行过程出错，系统也不是直接失败，而是会尝试修补或重新安排后续步骤。

#### 页面应写入的主要内容

- 系统会在关键节点进入“等待人工确认”的状态。
- 人工的选择会被记录下来，而不是只停留在界面点击层面。
- 系统在收到确认后，可以继续执行，并最终完成任务。
- 在恢复场景中，系统支持从参数修补升级到工具替换，再升级到 replan。

#### PPT 可直接填入的文字

标题下方说明句：

`本页展示一个代表性运行案例，重点说明系统如何在等待确认和失败恢复之间完成闭环。`

正文：

`案例回放中的关键现象`
- 在关键节点，系统会显式进入 `WAITING_*` 状态，而不是隐式继续执行
- 人工决策会写入 `PendingAction -> Decision -> EventLog` 证据链
- 遇到失败时，系统优先尝试局部修补，必要时再升级为 `replan`
- 在收到决策并完成恢复后，任务能够继续执行并收敛到终态

页底总结句：

`因此，这一页证明的是系统具备“可暂停、可确认、可恢复、可继续执行”的机制闭环，而不是单次运行结果本身。`

#### 最适合使用的图示

优先使用：

- `assets/recovery-hitl-overview.pdf`
- `assets/total-sequence.svg`
- 可选补充：`assets/single-step-sequence.svg`

如果只放一个图，优先使用：

- `assets/recovery-hitl-overview.pdf`

#### 推荐额外自制的小流程图

#### 图示图例建议

- `蓝色主线`：正常执行路径

### 第 7 页：实验案例二

这一页对应章节：`实验案例`

#### 页面标题建议

`实验案例二：中期机制验证基准结果`

#### 本页实验定位

- 这一页属于 `可复现实验结果页`，用于展示新的机制验证基准。
- 这组实验不宣称最终蛋白质设计效果更优，而是验证系统在控制、恢复、审计、路由和汇总方面的机制能力。
- 所有场景都来自仓库内可重复运行的集成检查，结果可以通过 `uv run pytest ...` 重新验证。

#### 为什么改成这组实验

- 旧的纵向实验结果很难支撑“方法效果显著提升”的说法。
- 当前系统最成熟、最有说服力的成果，其实是“控制能力、恢复能力和可审计性已经稳定成立”。
- 因此中期答辩更适合使用 `机制验证基准` 作为主实验结果页。

#### 页面应写入的主要内容

建议正文直接写这 4 条：

- 新基准共包含 `17` 个可复现场景，覆盖 `5` 个实验家族。
- 家族层面全部通过：Execution & Summary `3/3`，Gate `2/2`，HITL & Audit `4/4`，Planner Routing `3/3`，Recovery `5/5`。
- 证据文件完整率为 `100%`：`event_log 6/6`，`snapshot 2/2`，`report 3/3`。
- 关键机制覆盖也达到 `100%`，其中 `event_audit 7/7`、`patch_recovery 6/6`、`planner_routing 3/3`、`replan_escalation 3/3`、`result_summarization 3/3`。

`中期机制验证基准结果`

- `Evidence Complete Rate`：该家族中证据文件与信号检查均完整通过的比例

`capability_coverage.svg` 图例：
- `Scenario Count`：覆盖该能力的场景数量
- `Pass Rate`：与该能力相关场景的通过率
- `Family Count`：该能力跨越的实验家族数量

`artifact_support.svg` 图例：
- `Expected Count`：理论应产出的证据文件数量
- `Present Count`：实际落盘并可核对的证据文件数量
- `Present Rate`：实际落盘数量 / 理论数量

图例使用要求：

- 图表标题下方必须标注：`统计对象为仓库内可复现场景，不代表最终生物效果评价`
- 所有百分比建议统一写成 `100%`，不要同时混用 `1.0` 和 `100%`
- 如果同页放两张图，图例统一放在右下角，避免每张图各自写一套说明

#### 图表讲法建议

- `family_summary.svg`：强调系统不是只有一个 demo，而是已经形成覆盖多个机制家族的稳定验证集。

- 不要说“性能最好”或“效果显著提升”，应统一说“机制能力已经通过可复现场景验证”。

`因此，本次中期实验页的重点不再是证明最终生物效果已经最优，而是证明系统关键机制已经形成稳定、可复现、可审计的工程闭环。`
