# 论文文本降低AIGC修改说明

本文件用于指示Agent如何根据已有AIGC检测报告降低AIGC率。

请根据以下要求，对被检出的文本片段进行润色和改写。修改目标是让文本更接近本科论文中自然、平实、正式的写作风格，避免表达过于机械、生硬或具有明显 AI 生成痕迹。整体语言应当通顺好读，语义清晰，适用于本科论文正文语境。

## 一、整体修改目标

请在保持原文技术含义、逻辑关系和事实描述不变的前提下，对句子进行适度扩展、调整和润色。修改后的文本应当具备以下特点：

1. 表达自然，不要过于模板化或机械化。
2. 语气正式，但可以适度口语化，使其更接近本科论文中的正常表达。
3. 句子可以适当增加解释性内容，使行文更加饱满。
4. 避免过度压缩信息，减少“关键词堆叠式”的表达。
5. 不改变原文中的技术术语、代码标识符、配置项、接口路径和核心逻辑。

## 二、增加解释性和适度冗余

在修改过程中，可以适当增加解释性表达，使句子更完整、更自然。对于过于简短、直接的动词或动词短语，可以扩展为带有动作过程的表达。

例如：

- “管理”可以改为“开展……的管理工作”或“进行管理”。
- “交互”可以改为“进行交互”或“开展交互”。
- “配置”可以改为“进行配置”。
- “处理”可以改为“去处理……工作”。
- “恢复”可以改为“进行恢复”。
- “实现”可以改为“得以实现”或“来实现”。

同时，可以根据语境适当增加一些辅助词或连接结构，例如“了”“的”“地”“所”“会”“可以”“这个”“方面”“当中”等，使句子读起来更加自然。

例如：

- “提供功能”可以改为“提供了……功能”。
- “提供功能”也可以改为“有……功能”或“拥有……功能”。
- “系统处理请求”可以改为“系统会对请求进行处理”。
- “模块实现认证”可以改为“该模块可以完成认证功能的实现”。

需要注意的是，增加表达时应当适度，不能为了拉长句子而造成重复、啰嗦或语义混乱。

## 三、常用词语和表达方式替换

在保持技术含义不变的前提下，可以对部分高频词进行替换，使文本更自然，也避免重复使用同一表达。

### 1. 动词、介词和连接词替换

可以参考以下替换方式：

- “采用”可以改为“运用”“选用”或“把……当作……来使用”。
- “使用”可以改为“运用”“选用”或“进行使用”。
- “基于”可以改为“鉴于”或“基于……来开展”。
- “利用”可以改为“借助”“运用”或“凭借”。
- “通过”可以改为“借助”“依靠”或“凭借”。
- “和”“及”“与”在列举多项内容时，可以适当改为“以及”。
- “并”可以根据语境改为“并且”“还”或“同时”。
- “其”可以根据句子语境保留，也可以改为“它”，使表达更自然。

例如：

- “系统采用 JWT 进行认证”可以改为“系统选用 JWT 来进行用户认证”。
- “通过 Boto3 访问 S3 接口”可以改为“借助 Boto3 对 S3 接口进行访问”。
- “基于 Django 实现后端服务”可以改为“基于 Django 来开展后端服务的实现工作”。

### 2. 名词和形容词替换

可以根据语境适当替换部分名词或形容词，使表达更丰富。

- “原因”可以改为“缘由”或“主要原因”。
- “符合”可以改为“契合”。
- “适合”可以改为“适宜”。
- “特点”可以改为“特性”。
- “提升”和“提高”可以交替使用，避免重复。
- “极大地”可以改为“在较大程度上”或“极大程度上”。
- “立即”可以改为“马上”，但在论文中应谨慎使用，优先选择“及时”“快速”等更正式的表达。

例如：

- “该方案符合系统需求”可以改为“该方案与系统需求较为契合”。
- “该模块具有部署简单的特点”可以改为“该模块具有部署过程较为简单的特性”。

## 四、括号内容的处理方式

对于原文中的解释性括号，需要根据具体语境进行处理，尽量避免括号过多造成正文割裂。

### 1. 解释性括号

如果括号中的内容用于解释概念、说明缩写或举例，优先将其自然融入正文。可以使用“也就是”“即”“例如”“比如”“像……等”等表达。

例如：

- “ORM（对象关系映射）”可以改为“ORM，也就是对象关系映射”。
- “功能（如 ORM、Admin）”可以改为“功能，例如 ORM、Admin 等”。
- “对象关系映射（ORM）”可以改为“对象关系映射，即 ORM”。

如果括号内容只是非常基础的补充信息，且整合后会使句子显得冗长，可以在不影响理解的情况下谨慎省略。但不能删除重要的技术背景、关键示例或影响语义判断的信息。

### 2. 代码、文件名和类名旁的括号

对于紧跟在代码标识符、文件名、类名或模块名旁边的括号，可以将括号内容整合进正文，或者直接以解释性方式展开。

例如：

- “视图（views.py）中”可以改为“视图文件 views.py 中”。
- “权限类（admin_panel.permissions）”可以改为“权限类 admin_panel.permissions”。
- “配置文件（settings.py）”可以改为“配置文件 settings.py”。

如果括号中的内容本身就是代码标识符、文件路径或模块路径，必须保持原样，不能改写、翻译或错误转写。

## 五、句式调整和自然化表达

在保证论文正式性的前提下，可以对部分句式进行微调，使其更自然、更接近日常论文写作。

### 1. 适当使用“把”字句

在合适的语境中，可以将部分句子调整为“把”字句，使表达更顺畅。

例如：

- “系统会将对象移动到指定目录”可以改为“系统会把对象移动到指定目录中”。
- “该模块将请求转发给后端服务”可以改为“该模块会把请求转发给后端服务”。

### 2. 调整条件句表达

对于过于书面化的条件句，可以适当改为更自然的表达。不过在论文中仍需保持正式，不宜过度口语化。

例如：

- “若用户认证失败，则系统返回错误信息”可以改为“如果用户认证失败，系统就会返回相应的错误信息”。
- “若配置项缺失，则服务无法正常启动”可以改为“如果缺少相关配置项，服务就无法正常启动”。

### 3. 调整名词化表达

对于过度名词化、读起来生硬的句子，可以适当展开为动词性表达。

例如：

- “为了将业务逻辑与存储逻辑解耦”可以改为“为了实现业务逻辑和存储逻辑之间的解耦”。
- “完成用户认证的实现”可以改为“完成用户认证功能的实现工作”。

同时，也可以根据上下文在句首或句中增加“同时”“这样”“因此”“在这一过程中”等连接词，使段落衔接更加自然。

## 六、技术准确性要求

在润色过程中，必须严格保持技术内容的准确性。所有技术术语、代码标识符、库名、配置项、接口路径和文件名都不能被错误修改。

以下内容必须保持原样：

- 技术术语，例如 Django、RESTful API、Ceph、RGW、S3、JWT、ORM、MySQL。
- 代码片段和文件名，例如 views.py、settings.py、accounts.CustomUser、.folder_marker。
- 库名和依赖名，例如 Boto3、djangorestframework-simplejwt。
- 配置项，例如 CEPH_STORAGE、DATABASES。
- API 路径，例如 /accounts/api/token/refresh/。
- 模块名、类名、函数名、变量名和其他具有技术含义的标识符。

如果原文中包含代码、命令、接口地址、配置项或数据库字段，不得擅自翻译、改名、简写或纠正。即使这些内容看起来不够自然，也应当保持其技术形式不变。

## 七、核心逻辑保持不变

润色后的句子必须与原文表达相同的技术逻辑、因果关系和功能描述。不能因为语言调整而改变以下内容：

1. 系统模块之间的调用关系。
2. 数据流转过程。
3. 用户请求和系统响应之间的关系。
4. 配置项和功能行为之间的关系。
5. 技术方案的优缺点描述。
6. 原文中的限制条件、异常情况和处理逻辑。

如果某句话涉及系统行为，例如认证、授权、上传、下载、存储、恢复、删除、查询等操作，必须确保改写后的句子仍然准确描述原有行为。

## 八、修改说明

若无特殊要求，直接更改Word文档，但需要按照 AGENTS.md 中的要求，不要破坏交叉引用。

遵守以下规则：

1. 保留原有段落的大致结构。
2. 保留原有技术术语和关键标识符。
3. 保持本科论文正文的正式程度。
4. 避免过度华丽、夸张或宣传式表达。
5. 避免明显的 AI 模板化表达。
6. 句子应当自然、平实、通顺，适合直接放入论文正文。
